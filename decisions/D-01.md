### D-01. Серверная сессия с cookie

**Контекст:** нельзя гарантировать, что запросы на работу с сообщениями, обсуждениями и тегами исходят от пользователя с имеющимися на это правами. Нужен механизм авторизации, не позволяющий злоумышленнику делать операции от лица другого пользователя.

**Решение:** использовать серверную сессию с cookie. При вводе верных логина и пароля на клиенту возвращается случайный неподбираемый ID его сессии (session ID), заносящийся в cookie и передаваемый по HTTPS. Session ID должен быть действителен не более 7 дней.

**Обоснование:** решение даёт уверенность в том, кто пытается воспользоваться API, так как session ID выдаётся в обмен на логин и пароль, а при потере session ID его легко сделать недействительным на стороне сервера. Сам session ID не содержит пользовательских данных.

**Связанные угрозы:** T-1, T-4, T-5, T-6, T-7

**Связанные требования:** SR-1, SR-2, SR-3, SR-4, SR-6, SR-8

**Будущая проверка:**
Связанные требования уже содержат критерий приёмки. 

**Ограничения и последствия:** 
- Сервер должен иметь механизм создания и удаления пользовательских сессий.
- Обмен данными клиента и сервера должен проводиться по защищённому протоколу (например, HTTPS) с целью не дать доступ к данным при их перехвате.
- Мера **не защищает** при передаче session ID третьему лицу.
