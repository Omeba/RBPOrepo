### D-01. Авторизация через серверную сессию с cookie

**Контекст:** нельзя гарантировать, что запросы на работу с сообщениями, обсуждениями и тегами исходят от пользователя с имеющимися на это правами. Нужен механизм авторизации, не позволяющий злоумышленнику делать операции от лица другого пользователя.

**Решение:** использовать серверную сессию с cookie. При вводе верных логина и пароля на клиенту возвращается случайный неподбираемый ID его сессии (session ID), заносящийся в cookie и передаваемый по HTTPS. Session ID должен быть действителен не более 7 дней.

**Обоснование:** решение даёт уверенность в том, кто пытается воспользоваться API, так как session ID выдаётся в обмен на валидные логин и пароль, а при потере session ID его легко сделать недействительным на стороне сервера. Сам session ID не содержит пользовательских данных, а потому удовлетворяет SR-6.

**Связанные угрозы:** T-1, T-2, T-4, T-5, T-6, T-7

**Связанные требования:** SR-1, SR-2, SR-3, SR-4, SR-6, SR-8

**Будущая проверка:**
Связанные требования уже содержат критерий приёмки, например в SR-1. Более подробно:
1. Пользователь отправляет запрос на операцию, для которой у него нет прав
2. Сервер должен отклонить эту операцию без изменения существующих данных.

При попытке авторизации сервер сверяет данные авторизации. При успехе создаёт пользовательскую сессию, возвращает её ID пользователю по зашифрованному каналу. По истечении срока годности session ID или выходе из аккаунта он удаляется из записей сервера, считается невалидным.

**Ограничения и последствия:** 
- Сервер должен иметь механизм автоматического создания и удаления пользовательских сессий.
- У суперпользователя должна быть возможность
- Обмен данными клиента и сервера должен проводиться по защищённому протоколу (HTTPS) с целью не дать доступ к данным при их перехвате.
- В контексте T-2 и связанного SR-5 решение не предотвращает угрозу, но позволяет оперативно предпринять действия для её решения (через отмену действия session ID).
- Для генерации session ID должен использоваться криптостойкий случайный генератор для предотвращения подбора.
- Мера **не защищает** при передаче session ID от пользователя третьему лицу.
