## Функциональное ядро

| Критерий | Реализация | Фактическая проверка |
|---|---|---|

| Публикация только текстовых сообщений | `create_message`, `MessageForm`; вложения отклоняются | Сквозной сценарий, пустое сообщение, отсутствующее обсуждение, экранирование HTML |
| Удаление собственного контента и каскад сообщений | `delete_content` + ORM CASCADE | Удаление своего обсуждения и всех обычных сообщений |
| Модерация контента участников; защита других модераторов | `can_delete` и дополнительная проверка каскада | Положительные и отрицательные проверки для обсуждения, сообщения, тега и каскада |

| У обсуждения остаётся хотя бы один тег | Проверка после общей блокировки контента | Последний тег запрещён; два параллельных удаления оставляют один тег |
| Поиск по тегам и сортировка | Число совпавших тегов, затем функция возраста/активности | Проверены разные числа совпадений, отсутствие умножения COUNT при JOIN, возраст/активность, неправильные ID |
| Топ-3 обсуждений | Число сообщений, дата, ID | `test_top_three_and_countdown` |

| Редактирование отсутствует | Нет маршрутов редактирования; POST-поля ограничены | Запрос `/edit/` возвращает 404; GET удаления — 405 |
| Постоянное хранение и локальный запуск | SQLite; PostgreSQL в Docker volume; миграции | Обе базы мигрированы; HTTP `/` — 200, `/health/` — ok |

## Требования безопасности и решения

| Связь | Механизм и проверка | Граница утверждения |
|---|---|---|
| T-4 → SR-1 → D-01 | Гость не может создавать/удалять любой контент; проверено отсутствие изменений | Возвращается redirect на вход или 403; авторизация проверяется сервером |
| T-1 → SR-2 → D-01 | Чужие сообщения/обсуждения участнику запрещены, собственные разрешены | Дополнительный согласованный запрет каскадного удаления сообщений другого модератора |
| T-6 → SR-3 → D-01 | Собственное и контент участников доступны модератору; объекты другого модератора — 403 | Роль автора оценивается на момент операции |
| T-5 → SR-4 → D-01 | Автор определяется по сессии; подставные поля автора/пользователя/роли отклоняются | HTML-формы — единственный поддерживаемый формат записи; JSON и файлы отклоняются |
| T-2 → SR-5 → D-03 | Текущий пароль, валидация, уникальность, транзакция, версия сессии; все прежние сессии теряют доступ | Проверены логин отдельно, пароль отдельно, оба, две сессии, ошибочные данные, откат транзакции |
| D-03, конкурентность | Одинаковая блокировка строки пользователя для входа и смены данных | PostgreSQL: одновременно сменить данные из старой версии может только один запрос; вход со старым паролем не сохраняет доступ после смены |
| T-2 → SR-6 → D-01 | В cookie только случайный session ID; учётные данные не кладутся в сессию, ответы `no-store` | Сервер не может запретить пользователю вручную сохранить пароль или браузеру использовать менеджер паролей; логин публично показывается как автор |
| T-3 → SR-7 → IMPLEMENTATION-history | Снимки до/после каждой записи в одной транзакции, операторский откат | Проверено точное восстановление, многократные изменения, отмена отката, отсутствие учётных данных в снимках, отказ записи истории |
| T-7 → SR-8 → D-01 | Участник не создаёт/удаляет теги; модератор работает со своими | Проверено прямыми запросами, включая защиту последнего тега |
| D-01: срок, отзыв и транспорт | Абсолютное истечение ≤ 7 дней; logout уничтожает сессию; HttpOnly/SameSite | HTTPS/Secure cookies включаются в `DEBUG=0`; локальное демо работает по HTTP. Реальный TLS не развёрнут |
| CSRF и вывод текста | CsrfViewMiddleware, токены, POST, autoescape | Отсутствующий CSRF отклоняется; пользовательский HTML выводится как текст |

## Остаточные ограничения и подготовка к защите

- Это законченный локально запускаемый учебный форум. Публичная эксплуатация,
  TLS, эксплуатационное резервное копирование и нагрузочные испытания не проведены.
  Нет ограничения частоты входа/публикаций; публичному сервису оно понадобится.
- Поиск ранжирует найденный набор в памяти, снимки копируют весь контент;
  решение рассчитано на небольшой учебный объём. Операции записи сериализованы.
- Гарантия истории и правил предметной области действует для серверных сервисов
  приложения. Прямые команды SQL/ORM доверенного оператора способны их обойти.
  Добавленная `/admin/` доступна только для просмотра: стандартный CRUD запрещён,
  вход и смена пароля перенаправляются на защищённые маршруты форума.
- SQLite — простой локальный вариант. Гонки и блокировки проверены на PostgreSQL;
  не заявляется такая же конкурентная производительность SQLite.
- Полного формального соответствия всему EK1 не заявляется: исходный AI_USAGE.md
  пуст, CONTRIBUTIONS.md содержит шаблон, в THREAT_MODEL.md остались незаполненные
  разделы. По указанию пользователя эти файлы не редактировались. Команде требуется
  подтвердить свой вклад и проверку человеком, заполнить учебные документы и
  зафиксировать оцениваемый commit/tag. Публикация и отправка преподавателю не выполнялись.
- Этот результат не заменяет личное понимание кода и самостоятельные ответы на защите.

Факт помощи ИИ отдельно раскрыт в [IMPLEMENTATION_AI_USAGE.md](IMPLEMENTATION_AI_USAGE.md).
